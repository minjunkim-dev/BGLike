# BGLike

두 사람이 만드는 Godot 4 싱글 플레이 전술 RPG의 개발 작업명입니다. 게임의 정식 이름과 세계관은 첫 플레이 가능 구간을 만든 뒤 결정합니다.

개발 중인 상업용 PC 게임입니다. 아직 출시하지 않았습니다. 기능과 화면은 변경될 수 있습니다.

## 시작

- Godot 4.7.2 Standard와 Git LFS가 필요합니다. 이미 설치돼 있으면 그대로 씁니다.
- `git lfs install`을 한 번 실행하고 저장소를 복제합니다.
- 저장소 안에서 `git config core.hooksPath .githooks`를 한 번 실행합니다. 커밋 제목 검사·push 대상 브랜치 이름 검사·Git LFS hook이 함께 켜집니다.
- `project.godot`을 Godot에서 엽니다.
- F6으로 현재 장면을, F5로 메인 장면을 실행합니다.

명령줄에서는 다음으로 확인합니다.

```sh
make godot-install
make check
```

기존 편집기는 `GODOT=/Applications/Godot.app/Contents/MacOS/Godot make check`로 검사합니다.
플랫폼별 설치, 버전 검사와 캐시 없는 실행은 [공통 환경](docs/ENVIRONMENT.md)을 따릅니다.
전투 캡처의 차례 복귀 검사와 비활성 창의 Forward+ 직접 확인은 [캡처 검증](docs/CAPTURE_VERIFICATION.md)을 따릅니다.

문서·관리 파일만 바뀌면 공백과 Python 검사를 수행합니다. CI의 엔진 선택과 알림 조건은 [CI 구성](docs/CI.md)을 따릅니다.

전투 코드에서 공간 판단은 [CombatGrid](scenes/combat/grid.gd)가 맡습니다. 경로·도달 비용·점유·사거리와 공격 미리보기를 같은 유닛 배열에서 계산합니다.
[CombatSelection](scenes/combat/selection.gd)은 동작·대상·이동 미리보기의 선택·취소·확정을 맡습니다. [battle.gd](scenes/combat/battle.gd)는 입력 좌표·화면·연출을 연결합니다.
턴 자원·반응·피해 실행은 [CombatActions](scenes/combat/actions.gd), 적의 선택 우선순위는 [CombatEnemyAi](scenes/combat/enemy_ai.gd)에 둡니다.

## 협업 규칙

- 처음이라면 [참여 안내](CONTRIBUTING.md)를 읽습니다. Issue, 브랜치, 커밋, 문서, 개발 규칙을 한 장으로 요약했습니다.
- 작업은 GitHub Issue에 목표와 완료 조건을 적고 시작합니다. 작은 브랜치에서 PR을 열고 필수 CI와 리뷰 지적을 처리한 뒤 squash merge합니다. 동료 승인은 필수가 아닙니다.
- [협업 절차](docs/WORKFLOW.md)와 [AI 에이전트 지침](AGENTS.md)을 따릅니다. Claude Code와 Codex는 `AGENTS.md`의 공통 지침을 사용합니다.
- `main`에는 보호 규칙이 있습니다. 필수 검사(정책, smoke, CI)를 통과해야 병합할 수 있습니다. 자세한 운영 규칙은 협업 절차에 있습니다.
- `.godot/` 캐시는 커밋하지 않습니다. 장면과 스크립트 등 원본 파일은 커밋합니다. `.gitattributes`에 지정된 바이너리는 Git LFS로 관리합니다.

PR의 실행 검증은 GitHub Actions가 수행합니다. [Godot 캐시 설명](docs/CI_CACHE.md)은 CI 검사 서버와 Codex 원격 구현 환경의 역할을 구분합니다.

## 현재 범위

Issue #12의 M1 전투 프로토타입을 기반으로 3막 진행과 드랍·장착을 구현합니다. [Issue #163](https://github.com/minjunkim-dev/BGLike/issues/163)에서 평면 사각 격자로 전환했습니다. 640×360 기준 화면, 정수 배율과 픽셀 필터를 유지합니다. 맵은 10×10 사각 칸이며 타일은 16×16px입니다. 기존 9개 스테이지의 좌표와 몬스터 구성을 유지합니다. 현재 모든 칸은 높이0입니다. 규칙은 [게임 구조 기획서](docs/GAME_STRUCTURE.md)를 따릅니다.

[헥사 격자 시안](docs/HEX_GRID_PREVIEW.md)은 사각 높이 격자로 대체된 과거 기록입니다([Issue #136](https://github.com/minjunkim-dev/BGLike/issues/136)). 현재 구현은 평면 사각 전환까지입니다. 높이 상호작용·환경·점프는 후속 티켓 #164·#165·#166에서 구현합니다. 기준은 [게임 구조 기획서 6장](docs/GAME_STRUCTURE.md#6-사각-높이-격자)입니다. 16px 바닥은 검증용 V1 권장값이며 기획자의 최종 시안 승인과 구분합니다.

1-1부터 3-3까지 9번의 전투를 순서대로 진행합니다. 화면 위에 현재 막과 스테이지를 표시합니다. 승리 창에서 보상을 확인하고 정비한 뒤 다음 전투에 진입합니다. 3-3도 보상·정비를 마친 뒤 3막 졸업을 표시합니다. 전멸하면 현재 막의 첫 전투부터 다시 시작합니다.

같은 막에서는 HP·전투 불능·스킬 횟수를 유지합니다. 전투 불능 아군은 남은 스테이지에 나오지 않습니다. 막 시작과 막 재시작에서 전원이 최대 HP로 부활하고 스킬 횟수를 회복합니다. 표식·기절·이번 턴 효과는 전투 전환에서 해제합니다. 물약 시작 개수는0이며, 보유 물약은 막 시작이나 재시작으로 회복하지 않습니다.

`scenes/combat/battle.tscn`의 `stages`는 `scenes/combat/stages/`의 서로 다른 9개 데이터를 사용합니다. 각 막의 1스테이지는 거미, 2스테이지는 풋내기, 3스테이지는 고철로봇입니다. 적 7종의 수치는 막과 관계없이 같습니다. [스테이지 배치](docs/stages/README.md)에서 적 종류·수·좌표를 확인합니다. 아군은 전사 (1, 4), 궁수 (0, 5)에서 오른쪽을 보고 시작합니다. [M5 통합 검수](docs/M5_VERIFICATION.md)에서 자동 검사 범위와 직접 플레이의 확인 상태를 구분합니다.

승리하면 아이템1개를 보장하고 새끼 거미를 제외한 몬스터마다35%로 추가합니다. 처음 배치한 새끼와 엄마가 만든 새끼 모두 추가 드랍에서 제외합니다. 무기·방어구·회복 물약의 추첨 비중은2/2/3입니다. 장비의 두 수치를 얻은 막의 범위에서 독립 추첨합니다. 정비에서 전사·궁수 버튼으로 보상을 나눠 줍니다. 캐릭터마다 무기1칸·방어구1칸을 가집니다. 장착한 장비는 명중·피해·AC·최대 HP에 반영합니다. 방어구 교체는 잃은 HP를 보존하며, 최소 HP 1 보정으로 무료 회복을 만들지 않습니다. 교체한 이전 장비와 받지 않은 보상은 버립니다. 물약은 캐릭터별3개까지 가지며 정비에서1개씩 넘길 수 있습니다. 전투 불능 캐릭터도 수령·양도할 수 있습니다. 장비와 남은 물약은 막 재시작에도 유지합니다. 종류·수치·추첨 비중·추가 확률·물약 한도는 `scenes/combat/item_data.json` 하나에서 바꿉니다. [아이템 검증·데이터 안내](docs/ITEM_LOOT.md)에서 확정값을 확인합니다. 저장과 전체 인벤토리는 아직 없습니다.

막별 적 강화는 제거했습니다. 막별 난이도는 몬스터의 종류와 수로 바꿉니다. 기존 막별 장비 수치와 추첨 비중은 유지합니다.

2단계에서 `d20 + 민첩` 이니셔티브, 연속한 같은 편의 턴 묶음, 유닛별 이동·행동·보조 행동·반응 자원, 턴 종료를 추가했습니다. 아군 묶음에서는 왼쪽 위 초상을 눌러 유닛을 전환합니다. 선택 테두리와 아래 스킬 패널의 자원 마크가 함께 바뀝니다. 전환은 자원을 회복하지 않습니다. 턴 종료는 현재 유닛만 끝내며, 묶음의 전원이 끝내면 다음 묶음으로 넘어갑니다.

3단계에서 명중·유리/불리·내성·대결의 판정과 명중률 미리보기를 추가했습니다. 아군 턴에 지도 위의 적 도형을 한 번 누르면 오른쪽에 적의 HP·AC·상태와 명중률이 나옵니다. 기절한 대상과 원거리 공격자 옆의 적을 반영하고, 사거리 밖이면 0%와 이유를 표시합니다. 미리보기는 주사위를 굴리거나 자원을 쓰지 않습니다. 판정 결과는 주사위·선택 값·합계를 보존합니다.

4단계의 이동은 빈 칸을 한 번 우클릭해 경로를 보고 같은 칸을 다시 우클릭해 확정합니다. 다른 칸 우클릭은 목적지 미리보기만 바꿉니다. 유닛 몸통에 가려진 빈 칸도 우클릭으로 선택합니다. 이동은 상하좌우 4방향, 칸마다 비용1이며 남은 이동을 나눠 쓸 수 있습니다. 공격은 필드의 적을 한 번 좌클릭해 미리보기, 같은 적을 다시 좌클릭해 실행합니다. 빈 칸 좌클릭은 이동하지 않습니다. 겹쳐 보이는 유닛은 앞에 그려진 쪽을 선택합니다. 사거리 밖이나 자원이 없으면 실행하지 않습니다. 아래 스킬 패널에서 스킬·밀치기·물약을 선택하고, 자기 대상 동작은 같은 버튼을 다시 눌러 사용합니다. 기본 배치에서는 적이 사거리 밖이므로 먼저 이동해야 합니다.

기회 공격은 상대가 스스로 인접 칸을 벗어나기 전에 판정합니다. 아군은 확인 창에서 사용할지 고르고, 적 반응은 자동입니다. 반응을 기다리는 동안 다른 입력을 잠급니다. 밀치기와 물러서며 쏘기의 이동은 기회 공격을 받지 않습니다. 스킬과 물약은 턴 전환으로 회복하지 않습니다. HP0은 즉시 전투 불능이고 턴 순서에서 제거합니다. 기절한 다음 자기 턴은 자동으로 건너뛴 뒤 기절을 풉니다.

흘려내기와 충격 화살의 내성 DC는 `8 + 숙련2 + 능력치3 = 13`입니다. 전사 민첩+1의 흘려내기 성공률은45%이며, 피해를 굴리기 전에 확인합니다. 충격 화살은 빗나가도 행동과 사용 횟수를 모두 소비합니다.

[Issue #70의 이동·화살 연출](docs/COMBAT_DESIGN.md#9-7-이동과-화살-연출)은 이동과 화살 연출은 현재 사각 전투에서도 유지합니다. 이동은 칸당0.09초와 몸통3px 뜀으로 표시합니다. 궁수의 기본 공격과 충격 화살은0.16초 동안 화살을 날립니다. 연출 중 입력을 잠급니다. 기회 공격은 이동 직전에 처리합니다. 명중·흘려내기·피해는 화살 도착 뒤 처리합니다.

5단계에서는 화면 아래에 행동·보조 행동·반응 컨테이너를 둡니다. 제목의 ● ▲ ◆는 자원을 쓰면 ○ △ ◇로 바뀝니다. 버튼 오른쪽의 색 기호는 비용이고, 오른쪽 위 숫자 배지는 남은 막당 스킬 횟수 또는 보유 물약 개수입니다. 궁수는 반응 컨테이너를 숨깁니다. 자기 턴에 반응 항목을 눌러도 실행되지 않습니다. 적 턴에는 마지막 아군의 스킬 패널이 회색으로 남습니다.

자원 제목에는 이름과 채운/빈 마크만 표시합니다. 같은 자원이 여러 개면 개수만큼 마크를 표시합니다. [Issue #68의 기획](https://github.com/minjunkim-dev/BGLike/issues/68)에 따라 공격·스킬 호버에는 이름·효과·현재 사용할 수 없을 때의 이유만 표시합니다. 비활성 버튼도 설명을 보여 줍니다. 비용·남은 횟수·물약 개수는 버튼의 마크·숫자 배지로 표시합니다. 자원 제목에는 호버 설명을 표시하지 않습니다. 비용은 턴 자원이며 자기 턴 시작에 회복합니다. 횟수 배지는 턴 시작에 회복하지 않습니다.

[Issue #58의 기획자 코멘트](https://github.com/minjunkim-dev/BGLike/issues/58#issuecomment-6100264025)에 따라 왼쪽 고정 설명 패널과 오른쪽 조작 안내를 제거했습니다. 왼쪽 공간은 비웁니다. 초상에는 이니셔티브 숫자를 표시하지 않고 호버 계산식만 유지합니다. 전투 시작 로그에도 이니셔티브 계산식을 남기지 않습니다. [화면 정보·검증 안내](docs/COMBAT_UIUX.md)에 적용 화면과 후속 확인 절차를 기록했습니다.

이동 버튼은 두지 않습니다. 첫 우클릭에서 이동 가능한 칸은 파랑, 도착 후 기본 공격할 적이 있는 칸은 초록으로 표시합니다. 목적지의 경로와 도착 후 공격 가능한 적의 테두리를 유지합니다. 이동 미리보기의 설명과 남은 이동 칸 수는 표시하지 않습니다. 조작 안내는 이후 튜토리얼 단계에서 다룹니다. 이동에 성공하면 기본 공격 선택으로 돌아가므로 바로 적을 좌클릭해 공격할 수 있습니다. 이동은 행동을 소비하지 않으므로 이동→공격→남은 이동 순으로 사용할 수 있습니다. 이동 중 기회 공격에는 주의해야 합니다.

아군·적의 초상을 누르면 오른쪽 위에 HP·AC·능력치·명중·사거리·상태를 표시합니다. 현재 조작 가능한 아군 초상은 기존 조작 전환도 유지합니다. 다른 초상은 정보만 조회합니다. 실제 조작·진행 유닛의 이름을 따로 표시하므로 적 정보를 보면서도 아군을 조작할 수 있습니다. 필드의 적 공격 미리보기에서도 적 정보를 표시합니다. 초상 클릭은 공격을 준비하거나 실행하지 않습니다. 왼쪽 아래의 전투 로그는 최근 3줄을 표시하며, 유리·불리의 두 주사위, 내성·대결·반응과 표식 추가 피해를 기록합니다. 유닛 위에 HP 바, 기절 글자와 표식 ◎를 표시합니다. 판정과 HP 변화는 임시 숫자 팝업으로도 보입니다. 한쪽이 전멸하면 승리·패배 창에서 보상 확인 또는 막 재시작을 선택합니다.

적은 이니셔티브 순서대로 자동 행동하고 턴을 마칩니다. 풋내기 야만인은 조건에 따라 숨 고르기를 쓰고 접근해 공격합니다. 풋내기 궁수는 물러서며 쏘기로 거리를 벌린 뒤 기본 공격합니다. 새끼 거미는 접근해 공격합니다. 엄마 거미는 새끼 낳기를 우선합니다. 고철로봇은 과부하와 모델별 만능팔·회전회오리 규칙을 따릅니다. 현재 적은 몰아치기·표식·충격 화살을 쓰지 않습니다. 세부 조건은 [몬스터 문서](docs/monsters/README.md)를 따릅니다. 적 행동 사이에 짧은 간격을 두며, 아군 반응 확인 창에서는 선택할 때까지 기다립니다.

아군은 파랑, 적은 빨강이며 검과 활로 전사와 궁수를 구분합니다. 아군 턴은 실행 가능한 이동·행동·보조 행동이 없어도 자동으로 종료하지 않습니다. 턴 종료 버튼의 색만 강조합니다. 적 턴에는 이동·공격 입력과 턴 종료 버튼이 잠깁니다. 초상 정보 조회는 가능합니다. 편집기 직접 조작 확인과 7단계 전체 검수는 별도로 기록합니다.

규칙은 [전투 시스템 기획서](docs/COMBAT_DESIGN.md), 검수 기준은 [M1 개발 요청서](docs/DEV_REQUEST_M1.md), 용어는 [CONTEXT.md](CONTEXT.md)를 따릅니다. [M1 전체 검수 기록](docs/M1_VERIFICATION.md)은 검수 기준 28개를 자동 검사에 연결하고, 개발자 직접 플레이와 기획 검수의 기록 방법을 안내합니다. 대화, 저장, 플랫폼별 내보내기는 이번 단계에 포함하지 않습니다.
