# 최신 main Mac 입력 경계 검수

제품 소스: `7d533b636e7db0bd39ac5e82463611ab7921d15e`. macOS Apple M4 Pro, Godot 공식 4.7.2, Metal Forward+. 제품 파일 변경 없음.

- `limits-review.md`: Esc 드래그 취소, 물약 상한, 가방 가득 찼을 때 교환/해제, 폐기 모달 차단·취소·확인.
- `resume-review.md`: 새 프로세스의 실제 제목 화면 이어하기, 동일한 가방/장비/물약/위치/준비 상태 복원, 지도 복귀·전투 시작.
- 통과 원본: `session/limits/2/frames/` 26장 + `resume-session/resume/1/frames/` 7장. 33장 전체의 파일·상태 기록을 검사했고, 대표 원본(폐기 후·복원 직후·전투 시작 등)과 진행 중 실제 창을 직접 확인했다.
- 입력: 사용자 승인한 CGEvent 마우스 down/held-motion/up·Esc, CUA 앱 버튼/좌표 클릭. `drag.swift`는 대상 PID와 창을 검사하며 기존 권한을 사용한다. 시스템 권한을 바꾸지 않았다.
- 게임 결과는 실제 입력 경로로 발생했다. fixture는 유효한 장비/물약/가방 상태와 아군 순서만 준비했다. 별도 저장·설정 경로를 써 사용자 저장에 영향을 주지 않았다. 자동저장은 실제 battle process를 사용했다.
- 검수 시작1280×720. 복원 초기와 지도 복귀는1280×720이며 전투 시작 뒤3600×2196 확대 상태도 기록됐다. 이를 고정 해상도 검수로 표기하지 않는다.
- CUA 조회 timeout은 중복 입력 없이 로그와 원본으로 판정했다. 정비 상태 기록 중 추가 문자 키가 있어도 가방/장비 상태 변화는 없었으며, 사람의 조작감 증거로 해석하지 않는다.

제외 기록: 최초 limits는 사용자와 입력이 섞여 중단했다. 최초 resume는 probe의 잘못된 `title.tscn` 경로로 입력 전에 실패했다. 오류를 숨기지 않고 보존했다. 실제 `main.tscn`으로 교정한 별도 session/fingerprint에서 복원에 성공했다. 게임 결함으로 분류하지 않았다.

`check_evidence.py`는 원본 PNG 존재·상태 보존/변경·복원6필드·오류 없는 완료를 대조한다. `result.json`에 결과를 기록했다. PNG의 의미와 UI 입력은 작성자가 원본 화면에서 직접 확인했다. 독립 검토는 상태/로그 대조 범위로 구분한다.

사람의 청취·난이도·재미·조작감, 자연 전투 전체 완주는 검증 범위가 아니다. 밸런스 수치와 거미 증식 규칙은 변경하지 않았다.
