# BGLike Bugbot 보조 리뷰 규칙

이 프로젝트는 Godot 4.7.2 Standard와 GDScript를 사용하는 싱글 플레이 PC 게임입니다. 필요한 PR에서만 수동 보조 리뷰를 합니다. 기획에서 정하지 않은 제품 규칙을 제안으로 확정하지 않습니다.

다음 문서를 직접 읽고 관련 기준을 확인합니다. 경로 링크만으로 내용을 읽었다고 간주하지 않습니다.

- [전투 화면 정보 정리](../docs/COMBAT_UIUX.md): 입력·표시·tooltip·후속 확인의 기준.
- [M1 전체 검수 기록](../docs/M1_VERIFICATION.md): 과거 자동 검사와 직접 플레이의 구분. 과거 검수 결과를 현재 head의 성공으로 사용하지 않습니다.
- [AGENTS.md](../AGENTS.md): 제품·보안·LFS·권리 제약과 P0/P1/P2.
- [코딩 규칙](../docs/coding-standards.md): Godot 이름·타입·interface·검사.
- [독립 리뷰 절차](../docs/agents/review.md), [협업 규칙](../docs/WORKFLOW.md): 리뷰와 병합 경계.
- [문서 길잡이](../docs/agents/domain.md): Issue가 연결한 기획 문서와 관련 ADR. 파일이 없으면 누락을 기록합니다.
- [CI 구성](../docs/CI.md): 실제 검사 범위. PR의 Issue 합격 기준과 결정 코멘트를 함께 확인합니다.

상대 Markdown 링크는 Bugbot이 재귀적으로 포함합니다. README와 참여 안내로 돌아가는 사람용 링크는 GitHub URL로 유지해 중복 안내의 전체 확장을 막습니다. 원문 규칙과 기획 수치는 줄이지 않습니다. Issue가 요구한 다른 문서와 ADR이 자동 포함 목록에 없으면 직접 확인하거나 미확인으로 기록합니다.

전체 규칙은 100,000자, 문서별 규칙은 30,000자 한도입니다. 저장소의 상대 링크 합계는 95,000자 이하로 유지해 PR 자료용 여유를 둡니다. 실제 서버 포함은 `bugbot run verbose=true`의 규칙 표에서 두 문서·핵심 문서의 `included`와 `dropped`·`truncated`를 확인합니다. 로컬 합계만으로 실제 포함을 주장하지 않습니다.

지적에는 파일·위치, 구체적인 실패 조건, 사용자나 시스템에 주는 영향과 최소 수정 제안을 적습니다. 실제 결함과 문서화된 규칙 위반을 우선합니다. 근거 없는 스타일 지적과 일반적인 대규모 리팩터 제안을 남기지 않습니다.

로컬 작업자는 지적을 `실제 결함`, `오탐`, `판단 보류`로 분류합니다. 확실한 결함만 승인된 범위 안에서 수정합니다. Autofix와 공개 배포를 요청하지 않습니다. neutral check나 지적 0건을 합격 증거로 사용하지 않습니다. 필수 CI, 전체 diff의 독립 리뷰와 최종 head의 승인 정책을 대체하지 않습니다.
