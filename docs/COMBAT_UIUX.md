# 전투 화면 정보 정리

[Issue #58](https://github.com/minjunkim-dev/BGLike/issues/58)의 [기획자 코멘트](https://github.com/minjunkim-dev/BGLike/issues/58#issuecomment-6100264025)와 [사용자 구현 결정](https://github.com/minjunkim-dev/BGLike/issues/58#issuecomment-6137867077)을 반영한다. 전투 규칙과 클릭 입력은 유지한다. 상세 표시 규칙은 [전투 시스템 기획서9장](COMBAT_DESIGN.md#9-화면과-조작)을 따른다.

호버 내용은 [Issue #68](https://github.com/minjunkim-dev/BGLike/issues/68)과 [PR #67의 기획자 코멘트](https://github.com/minjunkim-dev/BGLike/pull/67#issuecomment-6138219432)의 2026-10-13 수정안을 따른다. 공격·스킬 호버에는 이름, 효과, 사용할 수 없을 때의 이유만 표시한다. 비용은 버튼 오른쪽 마크로 표시한다. 남은 스킬 횟수와 물약 개수는 숫자 배지로 표시한다. 호버에 비용·횟수·개수와 조작법·기호 설명을 반복하지 않는다.

## 정보의 표시 목적

| 표시 시점 | 정보 | 목적 |
| --- | --- | --- |
| 상시 | 막·스테이지·라운드·턴 묶음, 초상, 조작·진행 유닛, HP 바, 스킬 이름·비용 마크·횟수 배지, 턴 종료 | 진행 위치와 조작할 유닛, 가능한 행동을 찾음 |
| 유닛 선택·조회 | 이름, HP, AC, 능력치, 명중, 사거리, 상태 | 행동 중인 유닛과 조회 대상을 구분. 초상 조회는 조작 유닛의 자원을 바꾸지 않음 |
| 상세 호버 | 초상의 이니셔티브 계산식, 공격·스킬의 이름·효과·사용 불가 이유 | 필요한 시점에 효과를 조회. 비활성 버튼도 조회 가능 |
| 미리보기·선택 대기 | 이동 칸 색·경로·도착 시 공격 대상 테두리, 공격 명중률·판정 조건·실행 불가 이유, 반응 확인 창 | 실행 전에 대상과 결과를 확인. 호버는 동작을 실행하거나 자원을 쓰지 않음 |
| 로그·결과 | 최근3줄의 실제 판정·피해·반응, 승리·패배·보상·재시작 | 실행 결과를 확인. 시작 이니셔티브 계산식은 로그에서 제외 |

턴 순서 바 초상의 상태(현재 묶음·조작 중·조작 대기·턴 종료)는 [전투 시스템 기획서 9-3](COMBAT_DESIGN.md#9-3-영역별-내용)의 초상 상태 표를 따른다([Issue #140](https://github.com/minjunkim-dev/BGLike/issues/140)).

자원 제목의 채운/빈 모양은 색 없이도 남은 자원을 구분한다. 자원 제목에는 호버 설명을 표시하지 않는다. 유닛의 자원 최대 개수를 기준으로 채운 마크와 빈 마크를 함께 표시한다. 예를 들어2개 중1개를 쓰면●○다. 전부 쓰면○○다. 자기 턴 시작에는 같은 개수의 마크를 다시 채운다. 현재 게임의 턴 자원 최대 개수는 모두1이다. 실제 캐릭터의 수치와 자원당1개 소비 규칙은 유지한다.

우측 유닛 패널의 이동·턴 자원 줄을 제거한다. 남은 이동 칸 수는 표시하지 않는다. 좌측 동작·이동 설명과 우측 조작 안내를 제거한다. 좌측 공간은 비운다. 조작 방법은 이후 튜토리얼 단계에서 다룬다. 이번 변경에는 튜토리얼을 넣지 않는다.

호버 설명은0.5초 뒤에 HUD의 앞쪽에 표시한다. 스킬 설명은 아래 스킬 패널의 위에 띄운다. 설명 전체를 화면 안에 배치한다. 설명은 포인터 입력을 가로막지 않는다. 포인터가 버튼을 벗어나거나 반응·결과 창이 열리면 설명을 숨긴다. 초상도 같은 표시 방식을 쓴다.

## 적용 화면

실제 Godot4.7.2의 Metal 렌더링을 캡처했다. 기본 화면과 비활성 스킬의 호버를 보여 준다. 캡처는 고정한 턴 상태에서 만들었다.

## 검증과 후속 확인

비활성 창 캡처와 게임 진행 보존 검사는 [캡처 검증](CAPTURE_VERIFICATION.md)을 따른다.

자동 HUD 검사는 기본 상태, 유닛 조회, 이동·공격 미리보기, 반응·결과 창과 실제 포인터 입력을 확인한다. 이동 첫 우클릭은 미리보기다. 같은 칸의 두 번째 우클릭은 이동한다. 공격과 자기 대상 스킬의 두 번 클릭도 유지한다. 제거한 설명 패널의 빈 자리는 지도 입력을 막지 않는다.

640×360, 1280×720, 1920×1080과 기존 비정수 창 크기에서 화면 영역과 버튼 배지의 겹침을 검사한다. 활성·비활성 버튼 모두 실제 호버로 툴팁이 나타나는지 검사한다. 네이티브 실행은 기본 상태, 조회, 이동·공격 미리보기, 반응 창,2배 창의 호버를 별도로 캡처한다.

기획자 코멘트를 채택안으로 구현했다. 새 결과물의 기획자 재검수와 사람 플레이는 완료했다고 기록하지 않는다. 사람의 최종 가독성과 조작감 검수는 사용자의 결정대로 후속으로 남긴다.

1. Godot 편집기에서 메인 장면을 실행한다.
2. 640×360과 정수 배율에서 초상·HP·자원 마크·버튼의 가독성을 확인한다.
3. 활성·비활성 스킬과 초상에 마우스를 올린다. 이름·효과·사용 불가 이유의 잘림을 확인한다. 자원 제목에 호버가 없는지 확인한다. 버튼의 비용 마크와 횟수 배지를 확인한다.
4. 유닛 조회와 이동·공격 미리보기를 확인한다. 클릭 실행 방식이 유지되는지 확인한다.
5. 반응 창에서 사용·넘기기를 고른다. 로그와 결과를 확인한다.
