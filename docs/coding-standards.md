# 코딩 규칙

[AGENTS.md](../AGENTS.md)의 제품·실행·보안·권리 제약을 함께 따릅니다. 엔진 기준은 Godot 4.7.2 Standard와 GDScript입니다. 엔진 업그레이드와 외부 애드온은 별도 Issue에서 합의합니다.

## Godot 파일과 코드

- Godot 리소스 파일과 폴더 이름은 소문자 `snake_case`로 짓습니다. 관련 장면, 스크립트, 자산은 기능별로 가까이 둡니다.
- 새 GDScript에는 가능한 곳에 타입을 명시합니다. 전역 Autoload, 추상화, 기능 플래그 체계는 실제 사용처가 생길 때만 추가합니다.
- `.tscn`, `.tres`, `.gd`, `.uid`, 원본 자산과 필요한 `*.import` 설정을 커밋합니다. `.godot/` 캐시, 개인 설정과 비밀값을 커밋하지 않습니다.
- 큰 바이너리 원본은 [`.gitattributes`](../.gitattributes)의 Git LFS 규칙을 따릅니다. 같은 장면이나 바이너리를 동시에 수정할 때 파일 담당을 나눕니다.

## 변경 범위와 interface

1. 관련 Issue와 Issue가 연결한 기획 문서를 읽습니다. 관련 ADR이 있으면 [문서 길잡이](agents/domain.md)를 따라 읽습니다.
2. 바꿀 interface의 모든 호출자, 테스트, fixture와 설정을 확인합니다. 기존 helper와 주변 구조를 재사용합니다.
3. public contract, 검사 순서, 오류·취소 처리, trust·승인 경계와 자원 소유권을 보존합니다. 문서의 규칙이나 수치를 바꾸려면 먼저 Issue에서 결정합니다.
4. 목표를 충족하는 가장 작은 변경을 만듭니다. 실제 복잡한 동작을 작은 interface 뒤로 모으는 후보만 제안합니다. 합의한 범위 안에서만 리팩터합니다. 전체 재설계, 전체 포맷과 사용처 없는 dependency를 추가하지 않습니다.

## 검증의 증거

- 호출자가 사용하는 interface의 동작과 실패 경로를 검사합니다. 버그 수정 전 실패하는 기존 검사가 있으면 재사용합니다. 없으면 재현 검사를 추가합니다.
- 상수 재단언, 소스 문자열 순서와 성공만 반환하는 mock은 동작 검증의 근거가 아닙니다. 정적 검사는 정적 제약에 사용합니다.
- 단순 문서·설정 변경에 구현을 복제하는 테스트를 추가하지 않습니다. 설정을 읽는 도구와 실제 흐름을 확인합니다.
- 반복된 실제 결함은 재현 테스트, 자동 검사 또는 이 규칙에 반영합니다. 가상 문제를 위한 검사와 자동화를 만들지 않습니다.
- 필수 명령은 [README](https://github.com/minjunkim-dev/BGLike/blob/main/README.md)와 [CI 구성](CI.md)을 따릅니다. 자동 검사와 사람이 편집기에서 확인한 항목을 구분합니다.

리뷰 우선순위는 [AGENTS.md](../AGENTS.md#code-review-rules)에 있습니다. 리뷰 실행과 기록은 [독립 리뷰 절차](agents/review.md)를 따릅니다.
