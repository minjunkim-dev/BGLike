> 플레이어가 조작하는 캐릭터를 디자인할 때 따르는 순서와 채울 항목을 정한 뼈대 문서입니다. 개별 캐릭터의 능력치와 판정은 [능력치와 주사위 판정 기획서](../ABILITY_SYSTEM.md), 스킬·진행 규칙은 [전투 시스템 기획서](../COMBAT_DESIGN.md)와 [게임 구조 기획서](../GAME_STRUCTURE.md)가 기준입니다.
>
> - 기준일: 2026-10-23 (#321 능력치·주사위 대결 동기화)
> - **개정 안내 (2026-10-27)**: 능력치(자연 → 건강)와 판정(명중굴림·내성굴림, AC·DC)이 [능력치와 주사위 판정 기획서](../ABILITY_SYSTEM.md)로 개정되었습니다. 이 문서의 능력치·판정 표는 개정 전 규칙이며, 구현 PR이 맞출 때까지 기획서가 기준입니다.
> - **전사 재디자인 (2026-10-30)**: 전사를 컨셉부터 다시 디자인했습니다([전사](warrior.md)). 8장 목록과 10장 논의를 맞췄습니다. 고유 스킬 개수는 정하지 않고, 직업을 디자인할 때 디자이너가 정합니다.

## 1. 이 문서를 쓰는 법

- 새 캐릭터를 기획할 때 3장의 순서를 따르고, 7장의 시트를 복사해 캐릭터별 문서(8장)를 만듭니다.
- 시트의 수치와 규칙이 정해지면 전투 시스템 기획서나 게임 구조 기획서로 옮깁니다. 이 문서에는 컨셉, 키워드, 장단점, 역할처럼 **왜 그렇게 만들었는지**를 남깁니다.
- 세계관과 이야기는 M7에서 정합니다. 그 전까지 이름은 가칭을 씁니다.
- 외부 이미지 제작은 [공통 유닛 이미지 납품 규격](../UNIT_IMAGE_TEMPLATE.md)을 따릅니다. 현재 실제 도트 외형과 애니메이션은 [#193/#194 제작 기준](../PIXEL_ART.md)을 따릅니다. 이 아트 선택은 미확정 추상 컨셉이나 전투 수치를 확정하지 않습니다.

## 2. 디자인 원칙

| 원칙 | 상태 | 내용 |
|---|---|---|
| 컨셉 먼저 | ✅ | 소설 같은 추상 컨셉을 먼저 잡고, 그 컨셉에서 스킬을 만듭니다 |
| 컨셉이 기준 | ✅ | 컨셉이 스킬과 수치를 정하는 기준입니다 |
| 장단점 필수 | ✅ | 모든 캐릭터는 장점과 단점을 함께 가집니다. 단점이 없는 캐릭터는 만들지 않습니다 |
| 역할 하나 | ✅ | 캐릭터마다 장기인 역할(탱커, 딜러, 서포터)이 하나 있습니다 |
| 기존 동작 재사용 | 🟡 | 새 규칙보다 기존 동작(기절, 밀치기, 기회 공격, 유리/불리, 명중굴림·내성굴림)의 조합을 먼저 찾습니다 |

## 3. 디자인 순서 ✅

캐릭터는 **추상 컨셉 → 키워드 → 스킬 → 수치** 순서로 만듭니다. 기능(탱커가 필요하다)에서 시작하지 않고 인물(무리에서 쫓겨난 늑대인간)에서 시작합니다.

| 순서 | 할 일 | 결과물 |
|---|---|---|
| 1 | 추상 컨셉을 한 줄로 씁니다 | 컨셉 (4장) |
| 2 | 컨셉을 풀어 키워드를 3개 이상 뽑습니다 (상한 없음) | 키워드 |
| 3 | 키워드마다 전투에서 어떻게 드러날지 정합니다 | 스킬, 장점, 단점 (5장) |
| 4 | 나온 스킬을 보고 역할을 확인합니다 | 역할 (6장) |
| 5 | 수치를 정합니다 | 능력치, HP, 공격 가산·방어 가산, 기본 공격 |

- 스킬, 장점, 단점은 각각 **어느 키워드에서 나왔는지** 적습니다. 근거 키워드가 없는 스킬은 컨셉과 맞지 않는 스킬입니다.
- 스킬 개수는 정하지 않습니다. 직업마다 디자이너가 정합니다 (2026-10-30).
- 역할은 스킬에서 따라 나옵니다. 파티에 필요한 역할이 정해져 있으면 1단계 전에 정해 두고, 4단계에서 맞는지 확인합니다 🟡.

## 4. 추상 컨셉 ✅

추상 컨셉은 소설의 인물 소개처럼 쓴 한 줄입니다.

> 예: 무리에서 쫓겨난 늑대인간 · 세상에서 최초로 태어난 마법사

좋은 추상 컨셉의 조건 🟡:

| 조건 | 이유 | 나쁜 예 → 좋은 예 |
|---|---|---|
| **정체**와 **사연**이 함께 있음 | 정체만 있으면 흔한 직업이 되고, 사연이 개성을 만듦 | 늑대인간 → 무리에서 **쫓겨난** 늑대인간 |
| 결핍이나 갈등이 들어 있음 | 단점의 근거가 됨 | 강한 마법사 → **최초로** 태어난 마법사 (배울 곳이 없음) |
| 키워드가 3개 이상 나옴 | 스킬 3개를 만들 재료 | |
| 역할이나 수치를 직접 말하지 않음 | 기능에서 시작하면 컨셉이 수치 설명이 됨 | 방패를 든 탱커 |

- 늑대인간, 마법사 같은 일반 명사는 써도 됩니다. BG3나 다른 작품의 고유 인물·종족 이름은 쓰지 않습니다.
- 캐릭터 컨셉은 세계관(M7)보다 먼저 나옵니다. 컨셉이 세계관을 미리 정하는 셈이므로, 컨셉들이 한 세계에 함께 있을 수 있는지 M7에서 확인합니다 ❓.

## 5. 컨셉에서 스킬 만들기

### 캐릭터 특색의 공통 검수 기준 ✅

[Issue #140 후속 결정](https://github.com/minjunkim-dev/BGLike/issues/140#issuecomment-6298246327)은 기존 디자인 순서를 공통 검수 기준으로 채택했습니다.

| 확인할 것 | 기준 |
|---|---|
| 컨셉과 키워드 | 추상 컨셉1개에서 키워드를 3개 이상 뽑습니다(상한 없음). 역할·기능 요약을 컨셉 대신 쓰지 않습니다. |
| 스킬의 근거 | 고유 스킬·장점·단점마다 근거 키워드를 적습니다. 대상·조건·자원·효과 중 어디에서 그 키워드가 드러나는지 설명합니다. |
| 플레이어의 판단 | 각 고유 스킬이 플레이어에게 요구하는 판단을 적습니다. |
| 스킬 묶음 | 컨셉의 장점과 화면에서 알아볼 단점을 함께 드러냅니다. |

전사의 추상 컨셉과 키워드는 2026-10-30에 확정했습니다([전사](warrior.md)). 궁수는 2026-11-09에 컨셉·키워드·스킬 9개를 기획자와 정했습니다([궁수](archer.md)). 궁수의 현재 구현 3개 스킬은 옛 프로토타입이고 이 재디자인이 구현으로 바꿉니다. 고유 스킬 개수는 고정하지 않고 직업마다 디자이너가 정합니다. 전사의 현재 구현은 옛 프로토타입 스킬 3개이며 #407이 새 스킬로 바꿉니다.

### 스킬로 옮길 때의 질문

키워드를 전투 동작으로 옮길 때 쓰는 질문입니다 🟡.

| 질문 | 나오는 것 |
|---|---|
| 이 인물이 가장 잘하는 것은? | 대표 스킬, 장점 |
| 이 인물이 잃은 것, 못하는 것은? | 단점 |
| 이 인물은 언제 가장 강해지나? | 조건부 스킬 (유리, 추가 피해) |
| 이 인물은 동료와 어떻게 지내나? | 짝 (아군 연계) |
| 이 인물을 몰아붙이면 어떻게 되나? | 위기 때 쓰는 스킬, 약한 상대 |

스킬은 기존 동작(행동, 보조 행동, 반응, 유리/불리, 명중굴림·내성굴림, 기절, 밀치기)으로 먼저 만듭니다. 새 규칙이 필요하면 따로 적습니다.

### 스킬 폼 🟡

스킬 하나를 정할 때 항상 채우는 항목입니다. 2026-11-02에 전사 스킬 8개를 이 폼으로 정리했습니다([전사](warrior.md)). 동작의 6개 축은 [동작 유형 기획서 3장](../SKILL_TYPES.md#3-동작을-정의하는-축)을 따릅니다. 분류 6종은 합의 전입니다.

| 묶음 | 항목 |
|---|---|
| **A. 기본** | 이름 · 분류(공격 / 방어·생존 / 아군 지원 / 위치·이동 / 반응 / 패시브) 🟡 · 근거 키워드 · 플레이어의 판단 |
| **B. 비용** | 소비 자원(행동, 보조 행동, 반응, 이동력 N. 둘 이상이면 모두 소비인지 하나 선택인지) · 횟수(무제한 / 막당 N / 전투마다 N) · 사용 조건 |
| **C. 동작 정의** | 조준(자신 / 유닛 / 칸 / 환경 오브젝트) · 대상(적 / 아군 / 모두, 자신 포함 여부, 거리) · 범위 · 전달(근접 / 직사 / 곡사) · 판정(명중굴림 / 내성굴림 / 없음, 대상마다인지) · 수치(피해식) · 효과(즉발 / 잔류) · 부가 효과 |
| **D. 지속** (잔류 효과일 때) | 지속 N턴 · 소멸 시점 분류(지속형이 기본 / 이번 턴형 / 조건형 / 전투형. [동작 유형 기획서 4-5](../SKILL_TYPES.md#4-5-기간-시계-)) · 시전자 전투 불능 시(유지가 기본 / 해제) · 재시전(교체 / 합산 / 큰 값 유지 / 불가) |
| **E. 점검** | 새 규칙 · 기대 수치(기본 공격 대비 기대 피해와 명중률) · 호버 표기 · 기존 지침 위반(디버프 금지 등) |

- 시계의 기준은 기본적으로 시전자입니다. 다른 기준이 필요하면 그 동작 기획서에 예외로 명시합니다([동작 유형 기획서 4-5](../SKILL_TYPES.md#4-5-기간-시계-)). 즉발로 자원 수치를 바꾸는 동작(괴력의 사내의 이동력 0)은 분류 밖이고 자원 회복 시점에 복구됩니다.
- **세트 점검**은 캐릭터 단위로 합니다. 자원 분포, 키워드 커버, 장점·단점이 화면에서 보이는지, 스킬 사이의 강도 서열(예: 기본 공격 + 강철 돌진이 십자 베기를 앞서지 않는지), 새 규칙의 누적을 봅니다.

### 예시: 무리에서 쫓겨난 늑대인간

> 디자인 순서를 보여 주는 예시입니다. 채택한 캐릭터가 아니며 수치는 정하지 않았습니다.

| 키워드 | 전투에서 | 종류 | 새 규칙 |
|---|---|---|---|
| 혼자 | 인접한 아군이 없으면 공격에 유리 | 장점 | 상시 효과 (지금 스킬은 모두 직접 씀) |
| 혼자 | 아군 곁에 서면 힘을 못 냄. 전사와 붙어 싸우기 어려움 | 단점 | |
| 사냥 | HP가 절반 이하인 대상을 맞히면 피해 추가 | 스킬 | |
| 짐승의 몸 | 보조 행동으로 변신. 막당 1회. 이동력 증가, 대신 물약을 못 씀 | 스킬, 단점 | 변신 상태 |
| 쫓겨난 분노 | 의지 주사위가 작음. 마음 효과에 약함 | 단점 | |

→ 스킬이 혼자 사냥하는 쪽으로 모이므로 역할은 **딜러**입니다 (4단계).

### 예시: 세상에서 최초로 태어난 마법사

| 키워드 | 전투에서 떠올릴 수 있는 것 |
|---|---|
| 최초 | 마법의 이름도 규칙도 없음 → 스킬 효과가 주사위로 정해짐 |
| 배울 곳이 없음 | 스킬 수가 적거나, 막을 거치며 새로 깨우침 |
| 혼자 아는 힘 | 아군을 강화하는 스킬이면 서포터, 적을 약화하면 서포터 또는 딜러 |

## 6. 역할 ✅

| 역할 | 하는 일 | 지금 캐릭터 |
|---|---|---|
| 탱커 | 적의 공격을 받아 내고 버팀. 아군 딜러를 지킴 | 전사 |
| 딜러 | 적을 빠르게 전투 불능으로 만듦 | 궁수 |
| 서포터 | 아군을 회복·강화하거나 적을 약화함 | 없음 ❓ |

> 지금 적 AI는 사거리 안에서 HP가 낮은 대상을 노립니다 ([전투 시스템 기획서 7장](../COMBAT_DESIGN.md#7-적-ai)). 그래서 전사가 공격을 끌어 줄 수단이 없습니다. 탱커가 역할을 하려면 도발 같은 스킬이나 AI 조준 규칙이 필요합니다 ❓ ([게임 구조 기획서 5장](../GAME_STRUCTURE.md#5-캐릭터)). 전사는 2026-10-30 재디자인에서 기회 공격이 명중하면 적의 이동을 멈추는 효과(괴력의 사내)를 얻었습니다. [Issue #201](https://github.com/minjunkim-dev/BGLike/issues/201)이 권장한 "인접 아군 우선" 조준 규칙은 [기획자 답](https://github.com/minjunkim-dev/BGLike/issues/210#issuecomment-6330540479)으로 채택하지 않았습니다. 조준은 기획자가 정할 몬스터별 성향에서 다룹니다 ❓.

## 7. 캐릭터 시트

| 항목 | 내용 |
|---|---|
| 이름 | 가칭 |
| 추상 컨셉 | 정체와 사연이 있는 한 줄 (4장) |
| 키워드 | 컨셉에서 뽑은 3개 이상 |
| 역할 | 탱커 / 딜러 / 서포터 |
| 장점 | 2~3개. 수치나 동작으로 드러나야 함. 근거 키워드 |
| 단점 | 1~2개. 플레이어가 화면에서 알아챌 수 있어야 함. 근거 키워드 |
| 스킬 | 이름, 소비 자원(행동/보조 행동/반응), 횟수, 대상, 효과, 근거 키워드, 플레이어가 내릴 판단 |
| 능력치 | 힘, 민첩, 솜씨, 지능, 의지, 건강의 주사위 모양(면은 `1~n`) |
| 전투 수치 | HP, 공격 가산·방어 가산, 이동력 |
| 기본 공격 | 근접/원거리, 공격 능력치, 피해, 사거리. 근접이면 기회 공격이 가능하고 원거리는 불가 |
| 플레이 감각 | 이 캐릭터로 플레이어가 하는 판단. 예: "언제 버티고 언제 되받아칠까" |
| 짝 | 다른 캐릭터와 함께 쓸 때 생기는 연계 |
| 약한 상대 | 이 캐릭터가 혼자서는 상대하기 어려운 몬스터 |
| 외형 메모 | 실루엣과 색만. 에셋 출처는 #193에서 정함 ✅: 내장 image_gen의 독자적 생성 이미지 ([기획 현황](../DESIGN_STATUS.md), [제작 기준](../PIXEL_ART.md)) |

## 9. 새 캐릭터 체크리스트

- [ ] 정체와 사연이 있는 추상 컨셉이 있다.
- [ ] 키워드를 3개 이상 뽑았다.
- [ ] 스킬, 장점, 단점마다 근거 키워드가 있다.
- [ ] 장점과 단점이 모두 있고, 단점이 화면에서 보인다.
- [ ] 역할이 정해졌다.
- [ ] 새 규칙이 필요하면 무엇인지 적고 Issue에 질문을 남겼다.
- [ ] 이름과 텍스트에 BG3 고유 명칭을 쓰지 않았다.
