# GitHub Actions의 Godot 캐시

개발 기본 흐름은 로컬 구현 → PR → 자동 리뷰 → 로컬 수정·검증 → 사람이 병합입니다.
내 PC에서는 Godot 4.7.2 Standard로 게임을 실행하고 직접 조작을 확인합니다.
GitHub Actions는 PR의 코드와 리소스를 자동 검사합니다.
Codex PR 자동 리뷰는 변경 코드를 검토합니다. CI 통과와 직접 플레이 확인을 대신하지 않습니다.
이 CI 캐시는 Codex 원격 구현용 환경이나 Cloud Publish를 사용하지 않습니다.

Godot 워크플로는 공식 Linux x86_64 ZIP만 캐시합니다.
캐시 키에는 실행기의 OS·CPU, 엔진 버전 4.7.2와 저장소가 고정한 SHA-256이 들어갑니다.
캐시가 없으면 공식 파일을 다운로드하고, 복원한 파일도 매번 같은 SHA-256을 확인합니다.
복원한 ZIP의 체크섬이 다르면 그 파일을 삭제하고 공식 ZIP을 다시 다운로드합니다.
curl 호출은 한 번이며 일시적 오류에는 최대 3회 재시도합니다. 연결 제한은 15초, 각 전송 제한은 120초입니다.
전체 smoke 작업은 10분으로 제한합니다.
다운로드한 ZIP도 같은 체크섬을 다시 확인합니다. 재검증 실패 또는 다운로드 실패 시 설치를 중단합니다.
검증에 실패한 파일은 압축을 풀거나 실행하지 않습니다. 체크섬을 바꾸거나 검증을 끄지 않습니다.

같은 키의 GitHub Actions 캐시는 덮어쓰지 못합니다. 손상된 캐시가 남으면 재다운로드로 검사를 계속하지만,
다운로드 비용은 다시 발생합니다. 저장소의 Actions → Caches에서 해당 손상 캐시를 삭제하면 다음 성공 실행이
검증한 ZIP을 새로 저장합니다. 다른 캐시나 비밀값을 삭제할 필요는 없습니다.

캐시 명중 여부로 리소스 가져오기, 메인 장면 실행과 전투 테스트를 생략하지 않습니다.
`.godot/`, 사용자 DB, 비밀정보와 테스트 결과는 이 캐시에 넣지 않습니다.
GitHub Actions의 각 실행 요약에서 캐시 복원 결과, 명중 여부, 실제 ZIP 출처와 설치 결과를 확인할 수 있습니다.
ZIP 확보 경로는 `restored`(복원본 사용), `downloaded`(새 다운로드), `recovered`(손상 복원 후 재다운로드)입니다.
설치 실패 시에도 선택한 확보 경로를 기록합니다. 완료 여부는 설치 결과와 함께 읽습니다.
실행하지 못한 단계의 출력은 `unknown`으로 기록하며 캐시 미명중으로 해석하지 않습니다.
PR 캐시는 해당 PR의 반복 실행에서 복원되며 main에서 바로 재사용된다고 가정하지 않습니다.

현재 CI는 출시용 PC 패키지 내보내기나 운영 배포를 수행하지 않습니다.
