## 구현 감사

`scenes/combat/battle.tscn`은 `stages/act1_stage1.tres`부터 `act3_stage3.tres`까지9개 데이터를 순서대로 사용합니다. 각 데이터는 해당 적 배치 장면을 연결합니다. 적 종류·수·좌표는 [확정 배치표](stages/README.md#3-2-스테이지별-좌표-)와 일치합니다.

- 모든 스테이지의 맵은10×10 뾰족한 위 헥사입니다. 전사는 (1, 4), 궁수는 (0, 5)에서 오른쪽을 보고 시작합니다.
- 몬스터7종은 `enemy_definitions.gd`의 고정 수치를 사용합니다. 막별 적 강화는 없습니다. 아군 수치와 스킬은 유지합니다.
- 처음 배치한 새끼는 각각 이니셔티브를 굴립니다. 생성한 새끼는 엄마 직전에 생성 순서대로 들어갑니다. 생성 라운드에는 행동하지 않습니다. 엄마가 전투 불능이어도 새끼는 남습니다. 남은 새끼까지 처치해야 승리합니다.
- 처음 배치한 새끼와 생성한 새끼는 추가 드랍에서 제외합니다. 승리 보장 아이템1개는 유지합니다. 엄마와 보스는 일반 몬스터와 같은35%를 사용합니다. 1-1은 보장1개뿐입니다. 3-1은 엄마2마리분만 추가 추첨합니다.
- 장비의 막별 범위, 추첨 비중2/2/3과 물약 한도3을 유지합니다. 보상·정비·막 재시작·다음 막·3막 졸업 연결을 유지합니다.
- 세 보스는 기절 면역과 과부하를 사용합니다. 2000·3000은 만능팔을 사용합니다. 3000은 회전회오리와 확정 연계를 사용합니다. 과부하 자기 피해로 HP0이 되면 즉시 전투 불능입니다. 다른 적이 없으면 승리합니다. 이 정책은 사용자와 D0 결정의 확정값입니다.

## Forward Plus·정상 캠페인 후속 검증

2026-10-15 후속 요청으로 위 미확인 항목 중 Forward Plus 조작과 정상9스테이지 연속 진행을 추가 확인했습니다. 기준은 main `c996bf1f7c69f59f6f9bc89fe70f5d91921f106a`입니다. Godot4.7.2 공식 native 실행의 시작 로그는 `Metal 4.0 - Forward+ - Apple M4 Pro (Apple9)`입니다. 제품 메인 장면과 기본 렌더러를 사용했습니다. seed·이니셔티브·HP·배치·장비 초기값을 바꾸지 않았습니다. 스테이지 선택 wrapper·중간 재시작·스테이지 건너뛰기도 사용하지 않았습니다.

Codex가 같은 실행에서 실제 입력으로9개 전투를 모두 이겼습니다. 보상으로 얻은 장비와 물약만 사용했습니다. 최종 보상을 궁수에게 배분한 뒤 `3막 졸업` 버튼을 입력했습니다. 마지막 승리 화면은 정상 캡처로 확인했습니다. 졸업 문구는 접근성 트리로 확인했습니다. 졸업 시점의 정상 캡처는 확보하지 못했습니다.

### 확인 창 포커스 오류와 수정 검증

정상 캠페인은 종료 코드0으로 끝났습니다. 소유한 실행의 stdout에서 `_sub_window_grab_focus`의 `index == -1` 오류16개를 관측했습니다. `SCRIPT ERROR`와 `WARNING`은 없었습니다. 반응 창과 미수령 보상 폐기 창의 닫기에서 같은 오류를 재현했습니다. 좌표 취소에서도 stdout을 비운 뒤 새 오류1개를 확인했습니다. 파일 로그의 기록 지연 때문에 파일의 오류 수만으로 무오류를 판단하지 않았습니다. [Issue #122](https://github.com/minjunkim-dev/BGLike/issues/122)와 [PR #123](https://github.com/minjunkim-dev/BGLike/pull/123)에 수정 근거를 기록합니다.

Godot4.7.2는 모달 child를 제거하는 동안 부모의 이전 exclusive child로 접근성 포커스를 전달할 수 있습니다. 두 제품 확인 창에서 `exclusive = false`를 먼저 설정한 뒤 숨깁니다. OK의 자동 숨김을 끕니다. 다시 열 때 모달 상태를 복원합니다. 반응 결정과 보상 폐기의 기존 신호·자원·진행 규칙을 유지합니다.

수정한 제품 파일로 별도 Forward Plus native 실행을 확인했습니다. 정상1-1 전투에서 반응 창의 접근성 취소·좌표 취소·Esc·닫기 버튼·좌표 확인을 입력했습니다. 확인한 흘려내기는1회만 소비됐습니다. 다음 적 행동과 아군 턴도 이어졌습니다. 보상 창은 별도 native probe에서 실제 `CombatPreparation`과 고정 미수령 보상1개를 사용했습니다. Enter 기본 취소·취소 버튼·Esc와 반복 재열기를 확인했습니다. 보상1개가 유지됐습니다. 명시적 확인은 완료 신호1회와 남은 보상0개를 기록했습니다. 이 probe를 정상 캠페인 승리나 실제 다음 스테이지 진행의 근거로 사용하지 않습니다. 실제 진행 연결은 기존 통합 검사로 확인합니다.

두 수정 native 실행은 종료 코드0으로 끝났습니다. stdout에 새 오류·경고·스크립트 오류가 없었습니다. headless 회귀는 접근성 포커스 전달을 명시적 모형으로 검사합니다. native 접근성이 headless에서 동작했다고 기록하지 않습니다. 수정 전 실패와 수정 후 통과를 확인했습니다. 반응 창의 취소·확인·닫기·Esc·스테이지 시작·결과 표시와 폐기 창의 Enter·취소·닫기·Esc·명시적 확인을 검사합니다.

CUA 캡처가 흰색이거나 좌표 입력이 창을 찾지 못하는 현상은 일부 남았습니다. 사용자는 같은 시점의 실제 전투 화면이 정상이라고 확인했습니다. 일반 창과 전체 화면 전환으로 일부 입력을 복원했습니다. 이 도구 현상을 제품 화면 오류의 증거로 사용하지 않습니다. 폐기 창의 닫기 버튼은 수정 native probe에서 직접 누르지 못했습니다. 해당 경로는 headless 회귀로 확인했습니다.

사람의 조작감·가독성 검수와 장시간 성능은 미확인입니다. #113의 사람 확인 예외는 위 당시 기록에만 적용했습니다. 이번 수정의 사람 확인 여부와 최종 head 독립 리뷰·필수 CI·병합·main CI 결과는 PR #123에 기록합니다. 공개 배포와 Draft CD는 실행하지 않습니다.

## 정리한 차이와 남은 범위

구현 전·시험 전투 반복·막별 적 강화 잔존이라는 설명을 현재 소스에 맞췄습니다. 과부하 HP0과 회전회오리의 옛 미정 표시를 확정 명세와 구현 상태로 바꿨습니다. M1의 전사·궁수 AI 설명과 과거 검수 수치·캡처는 과거 기록임을 표시했습니다.

막별 장비 수치 재검토와 새 배치의 드랍 기대값 재계산은 후속 기획입니다. 지형·장애물·아트·번역도 이번 범위 밖입니다. 새끼 수 상한이나 별도 성능 합격 수치를 정하지 않습니다. 공개 배포와 Draft CD는 수행하지 않습니다.
