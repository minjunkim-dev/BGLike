# 아이템 기획 폼

> 아이템 하나를 기획할 때 반드시 정할 항목과 선택 항목, 수치 가감의 종류와 적용 규칙을 정리한 문서입니다. 데이터 파일(`item_data.json`)의 필드 정의가 아닙니다.
>
> - 기준일: 2026-11-05 (기획 논의로 확정)
> - 상태: ✅ 기획 확정, 구현 전입니다. 현재 구현은 가산 4종만 지원합니다([아이템 안내](ITEM_LOOT.md#한-파일에서-바꾸는-아이템-데이터)).
> - 용어는 [CONTEXT.md](../CONTEXT.md)와 [능력치 기획서](ABILITY_SYSTEM.md)를 따릅니다.
> - 표시: ✅ 정해짐 · ❓ 정해야 함 · ⏸ 보류

## 1. 쓰임새

새 아이템을 추가하거나 기존 아이템을 점검할 때 이 폼을 채웁니다. 필수 항목이 하나라도 비면 기획 미완성입니다. 폼을 채운 뒤에 개발 요청과 데이터 입력으로 넘깁니다.

## 2. 폼

### 필수

| 항목 | 묻는 것 |
|---|---|
| 이름 | 플레이어에게 보이는 이름 |
| 분류 | 무기, 방어구, 회복 물약 중 무엇인가 |
| 한 줄 역할 | 설계 의도. 이 아이템을 쓰면 무엇이 달라지는가 |
| 게임 내 설명 | 게임 안에서 플레이어가 읽고 "이런 아이템이구나" 하고 이해할 문구 |
| 수치 가감 | 바뀌는 수치와 가감 값. 한 줄 이상 ([3장](#3-수치-가감)) |
| 획득 | 어느 막에서 어떻게 얻는가. 드랍 비중, 보상 조건 |
| 제약 | 한도, 장착 조건, 중복 규칙. 없으면 `없음`이라고 적습니다 |

### 선택

| 항목 | 묻는 것 |
|---|---|
| 부가 효과 | 수치 가감 밖의 특수 규칙 |
| 시너지·충돌 | 다른 아이템, 직업, 스킬과의 관계 |
| 등급·희소성 | 현재 보류입니다 ⏸ |
| 플레이버 | 세계관 연결, 분위기 문구 |
| 아이콘 방향 | 외형 콘셉트, 직업별 변형 |
| 밸런스 메모 | 기대 효과와 위험 요소 |

게임 내 설명은 수치에서 자동으로 만들고, 플레이버만 직접 씁니다 ✅ `개발 결정`([Issue #456](https://github.com/minjunkim-dev/BGLike/issues/456)).

## 3. 수치 가감

수치 가감 한 줄은 `종류 · 대상 · 가감 값`입니다. 값은 `+n` 또는 `−n`이며, 음수는 단점이나 대가로 씁니다. 회복 물약의 회복 줄은 가감이 아니라 주사위 식(예: `2d4+2`)을 씁니다. 막별 범위(`[최소, 최대]`)로 적을 수 있습니다. 한 아이템에 여러 줄을 둘 수 있습니다.

| 종류 | 대상 | 더하는 곳 |
|---|---|---|
| 능력치 가감 | 힘, 민첩, 솜씨, 지능, 의지, 건강 | 그 능력치의 **주사위 굴림값**과 **표준값** |
| 공격 가산 | 공격 | 명중굴림의 공격 굴림, DC |
| 방어 가산 | 방어 | AC, 내성굴림 |
| 기타 가산치(피해 보정) | 피해 | 피해 굴림 |
| 고정 수치 | 최대 HP, 최대 이동 | 해당 수치 |
| 회복 | 회복량 | 물약의 회복. 가감이 아니라 주사위 식 값 |

- **능력치 가감**은 주사위의 면 수를 바꾸지 않습니다. 굴린 결과값에 더하고, 그 능력치를 쓰는 모든 곳(공격·피해·내성·이니셔티브)에 따라갑니다. 고정값이 필요한 AC와 DC에는 표준값에 더합니다.
- **가산**은 해당 계산에만 붙습니다. 능력치와 무관합니다.
- 같은 효과를 능력치 가감으로 줄지 가산으로 줄지는 범위로 정합니다. 예를 들어 민첩 가감 +1은 AC뿐 아니라 이니셔티브와 민첩 내성굴림에도 +1이고, 방어 가산 +1은 AC와 모든 내성굴림에 +1입니다. 폼의 "한 줄 역할"에서 이 선택의 이유를 적습니다.

### 적용 식

```text
굴림값     = max(1, 능력치 주사위 눈 + 레벨 + 능력치 가감)          (유리/불리로 눈을 고른 뒤 더함)
공격 굴림  = 공격 능력치 굴림값 + 공격 가산
내성 굴림  = 내성 능력치 굴림값 + 방어 가산
피해 굴림  = 피해 능력치 굴림값 + 기타 가산치
AC         = max(1, max(1, 민첩 표준값 + 민첩 가감) + 방어 가산)
DC         = max(1, max(1, 시전 능력치 표준값 + 그 능력치 가감) + 공격 가산 + 스킬 보정)
이니셔티브 = 민첩 굴림값
```

스킬 식 안에 굴림값이 들어가면 능력치 가감도 그 안에 들어갑니다. 예를 들어 휩쓸기의 현재 기획식([전사 문서](characters/warrior.md))은 다음과 같습니다.

```text
피해 = ⌈힘 굴림값 ÷ 2⌉ + 기타 가산치
```

레벨은 굴림값 안에 한 번만 들어갑니다([#407 답 4](https://github.com/minjunkim-dev/BGLike/issues/407#issuecomment-6568715948)의 `⌈(힘 d20 눈 + 레벨) ÷ 2⌉`). 능력치 가감도 굴림값에 들어 있어 ÷2 안으로 들어갑니다. 힘 가감 +2는 ÷2를 받아 대상당 약 +1이고, 기타 가산치 +2는 ÷2 밖이라 대상당 +2입니다. 스킬마다 기타 가산치의 배수가 다르므로(십자 베기 2배, 강철 돌진 0배) "한 줄 역할"과 "시너지·충돌"에 적용 범위를 적습니다([전사 문서](characters/warrior.md)).

### 하한

가감 값은 음수여도 되지만, **계산된 값은 최소 1**입니다. 하한은 결과에만 적용합니다.

| 계산된 값 | 하한 |
|---|---|
| 굴림값 | 1 |
| 표준값(능력치 가감 반영 후), AC, DC | 1 |
| 피해 굴림 (대상당) | 1 |
| 최대 HP | 1 |
| 최대 이동 | 1칸 |

최대 이동 0칸(이동 불가)이 필요한 아이템은 이 하한과 충돌하므로 따로 기획합니다. 지금은 허용하지 않습니다 ✅ `개발 결정`([Issue #456](https://github.com/minjunkim-dev/BGLike/issues/456)).

### 절대면과 유리/불리 ✅

- 절대성공·절대실패는 주사위 **눈** 기준입니다. 능력치 가감과 가산에 관계없이 정해집니다([절대면](../CONTEXT.md)).
- 유리/불리로 두 번 굴려 눈을 고른 뒤에 능력치 가감을 더합니다.

## 4. 작성 예시

실제 아이템이 아니라 작성법을 보이는 예시입니다.

| 항목 | 내용 |
|---|---|
| 이름 | 무거운 판금 갑옷 |
| 분류 | 방어구 |
| 한 줄 역할 | 단단히 버티는 대신 움직임과 반응이 무뎌지는 방어구. 방어 가산은 내성굴림까지 막고, 민첩 가감은 이니셔티브에도 영향을 준다 |
| 게임 내 설명 | 두꺼운 판금이 공격을 막아 주지만 걸음이 무겁고 반응이 느려진다. |
| 수치 가감 | 방어 가산 +3 · 최대 HP +5 · 민첩 가감 −1 · 최대 이동 −1 |
| 획득 | 2막 방어구 추첨 풀 |
| 제약 | 없음 |

AC는 방어 가산 +3과 민첩 가감 −1이 합쳐져 +2입니다. 이니셔티브 굴림은 −1이고, 최대 이동은 기본 6칸에서 5칸입니다.

## 5. 정할 것

| 항목 | 상태 |
|---|---|
| 게임 내 설명의 형식(직접 작성 또는 자동 생성) | ✅ `개발 결정`: 수치에서 자동 생성([Issue #456](https://github.com/minjunkim-dev/BGLike/issues/456)) |
| 능력치 가감과 가산의 막별 수치 범위 | ❓ [Issue #205](https://github.com/minjunkim-dev/BGLike/issues/205)에서 다룹니다 |
| 최대 이동 0칸을 허용하는 아이템 | ✅ `개발 결정`: 허용하지 않음, 최소 1칸([Issue #456](https://github.com/minjunkim-dev/BGLike/issues/456)) |
| 등급·희소성, 직업 제한 | ⏸ 보류 |
| 전투 UI의 능력치 가감 표시 | ✅ `개발 결정`: 가산 표기를 확장해 `힘 d20+2`로 보입니다. 유닛 패널·호버에 적용했고 확인 창은 가감이 없어 그대로입니다([Issue #456](https://github.com/minjunkim-dev/BGLike/issues/456)) |
| 구현 요청과 개발 | ✅ 전투 코드가 능력치 가감 6종(`strength_modifier` 등)과 `max_movement`를 읽습니다([Issue #456](https://github.com/minjunkim-dev/BGLike/issues/456)). `item_data.json`의 시험 아이템은 가산 4종만 쓰며, 가감을 쓰는 아이템과 수치 범위는 [Issue #205](https://github.com/minjunkim-dev/BGLike/issues/205)에서 정합니다 |
