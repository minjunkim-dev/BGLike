# 주사위 굴림 연출 기본값

[Issue #306](https://github.com/minjunkim-dev/BGLike/issues/306)의 [기획자 답변](https://github.com/minjunkim-dev/BGLike/issues/306#issuecomment-6406245423)에서 시작한 주사위 연출 기획이다. 굴림의 종류별로 연출 기본값을 정한다. 2026-10-31 기획자와 개발 논의 결과를 기록한다. 기획자가 구현 착수를 허용했고, 아래 [구현 상태](#구현-상태)대로 만들었다.

흘려내기는 [#423](https://github.com/minjunkim-dev/BGLike/issues/423)에서 전사 재디자인으로 폐지해 이 문서의 굴림 목록에서 뺐다. 성스러운 장막과 전투의 함성의 굴림은 피해·회복과 같이 연출 없이 팝업·로그만 보인다.

## 시점과 범위

- M7에는 넣지 않는다. M6에서 만든다.
- 전투 중 굴림이 대상이다. 전투 밖 보상 추첨(`loot.gd`)은 이번 범위가 아니다.
- 기획자 후보 8개 연출 유형 중 이번에 쓰는 것은 아래다.

| 유형 | 내용 | 이번 사용 |
|---|---|---|
| 1 | 아무 연출 없음 | 사용 |
| 2 | 굴림 사운드 | 사용 |
| 3 | 성공/실패 애니메이션 | 사용 (숫자 + 색상) |
| 4 | 성공/실패 사운드 | 사용 |
| 5 | 굴림 애니메이션 | 사용 |
| 6 | n회 굴림 애니메이션 | 사용 (유리·불리) |
| 7·8 | 굴림 대결 애니메이션·승패 사운드 | 보류 |

## 굴림 카테고리와 기본값

굴림을 스킬 이름이 아니라 성격으로 나눈다. 새 스킬은 카테고리를 고르면 연출이 정해진다.

| 카테고리 | 성격 | 현재 굴림 | 연출 |
|---|---|---|---|
| 명중 | 공격 굴림 대 AC | 일반 공격, 기회 공격 등 | 애니메이션 + 굴림음 + 결과음 |
| 내성 | 굴림 대 정해진 기준값 | 독 제거, 회전회오리, 만능팔, 기름 미끌거림, 독안개, 밀치기(몬스터만 굴려 지금은 연출 없음) | 애니메이션 + 굴림음 + 결과음 |
| 대결 | 양쪽이 굴려 총합 비교 | 없음 | **보류** |
| 피해 | 피해량 주사위 | 무기 피해, 상자 피해, 화상 틱 (표식 d6은 #528에서 폐지) | 없음(유형 1) |
| 회복 | 회복량 주사위 | 숨 고르기, 물약 | 없음(유형 1) |
| 이니셔티브 | 턴 순서 | 전투 시작 굴림 | 없음(유형 1) |
| 무작위 선택 | 후보 중 하나 고르기 | 소환 칸, 착지 칸 | 없음(유형 1) |

- 회전회오리([#389](https://github.com/minjunkim-dev/BGLike/issues/389))와 만능팔·밀치기([#391](https://github.com/minjunkim-dev/BGLike/issues/391))는 대결에서 대상의 내성굴림으로 옮겨져 내성 기본값을 따른다. 지금 대결 굴림은 없다.
- `개발 결정`([#306](https://github.com/minjunkim-dev/BGLike/issues/306), PR #419): 회전회오리는 대상마다 연출이 끝난 뒤 피해를 낸다. 만능팔과 독 제거는 AI가 기다리지 않고 부르는 동작과 턴 시작 처리를 멈추지 않도록, 연출을 기다리지 않는다. 그래서 만능팔은 주사위가 구르는 동안 끌려온다. 굴림이 이어지면 먼저 온 굴림부터 결과까지 하나씩 보인다([#420](https://github.com/minjunkim-dev/BGLike/issues/420)). 기획자가 나중에 바꿀 수 있다.
- 피해·회복·이니셔티브·무작위 선택은 애니메이션도 사운드도 없다. 기존 팝업·로그·타격음(`hit.ogg`)은 그대로다.
- 명중·내성의 연출은 **굴리는 주체가 아군일 때만** 보인다(아래 [굴리는 주체](#굴리는-주체)).

## 연출 규칙

### 굴림음과 결과음

굴림음(2)과 결과음(4)은 **누적**한다. 굴림이 시작될 때 굴림음, 결과가 확정될 때 결과음이 난다.

### 굴리는 주체

주사위 연출은 **아군이 굴릴 때만** 보인다. 몬스터의 굴림은 연출 없이 기존 팝업과 로그만 남긴다.

| 굴림 | 아군이 굴림 | 몬스터가 굴림 |
|---|---|---|
| 명중 | 연출 | 팝업·로그만 |
| 독 제거 | 연출 | 팝업·로그만 |

- 몬스터가 아군을 공격할 때의 명중굴림도 연출하지 않는다.
- 이 규칙으로 적 턴의 연출이 줄어 4배속 빠르게 보기에서 읽히는지 걱정이 줄어든다.

### 주사위 모양

면 수에 맞는 다면체 모양을 살려서 굴린다. 멈춘 윗면에 결과 숫자를 보인다. 절대성공면·절대실패면이 나오면 그 면에 강조를 더한다. 3D 모델이나 2D 스프라이트 중 무엇으로 만들지, 면 수별 자산은 개발자가 정한다.

### 기준값 표기

기준값(명중의 AC, 내성의 기준)은 **굴리기 전부터 게이지 아래에 고정으로 보인다.** 굴림이 끝나도 그대로이고, 합계는 게이지 마커 위에 나타난다. 식(`9 +3 = 12 < AC 13`)은 화면에 보이지 않는다.

- `개발 결정`([#306](https://github.com/minjunkim-dev/BGLike/issues/306)): 식 대신 판정 단어·여유·게이지로 결과를 보인다. 근거는 플레이어가 알고 싶은 것이 "얼마나 아슬아슬했나"라는 점이다. 대안은 식을 그대로 두는 것이다. 기획자가 나중에 바꿀 수 있다.
- 기준의 이름을 붙인다. 명중은 `AC`, 내성굴림(독 제거·회전회오리·만능팔·기름 미끌거림·독안개)은 `DC`로 표기한다.
- 절대성공·절대실패면은 기준과 상관없이 결정되므로 게이지 전체를 결과 색으로 채우고 합계 마커는 굴리는 동안에도 보이지 않는다.

### 결과 표시

- 판정 단어와 여유(합계 − 기준값)를 보인다. 예: `성공  +2`, `아깝게 실패  -1`. 여유가 0이면 `±0`이다. 절대면은 단어만 보인다.
- 성공과 실패는 색상과 단어로 구분한다. 색에만 기대지 않는다. 기존 글자 팝업(`빗나감` 등)도 함께 쓴다.
- 게이지는 기준값을 가운데 눈금으로 두고 왼쪽을 실패 구간, 오른쪽을 성공 구간으로 깐다. 합계 마커는 굴리는 동안 왼쪽 끝에서 결과 위치로 움직이고, 멈추면 합계를 보인다. 여유가 ±6을 넘으면 끝에 붙는다.
- 절대성공면·절대실패면은 일반 성공/실패와 같은 색에 **강조**(큰 주사위, 노란 외곽선)를 더한다.

| 등급 | 조건 | 단어 |
|---|---|---|
| 절대성공 | 절대성공면 | 절대성공 |
| 큰 성공 | 성공, 여유 +5 이상 | 큰 성공 |
| 성공 | 성공, 여유 +2 ~ +4 | 성공 |
| 아슬아슬한 성공 | 성공, 여유 0 ~ +1 | 간신히 성공 |
| 아슬아슬한 실패 | 실패, 여유 −1 | 아깝게 실패 |
| 실패 | 실패, 여유 −2 ~ −4 | 실패 |
| 큰 실패 | 실패, 여유 −5 이하 | 큰 실패 |
| 절대실패 | 절대실패면 | 절대실패 |

- 등급은 규칙의 성공/실패를 바꾸지 않고 여유로만 세분한다. 경계값과 게이지 범위는 임시이며 플레이로 정한다(`BIG_MARGIN`, `NARROW_SUCCESS_MARGIN`, `NARROW_FAILURE_MARGIN`, `GAUGE_RANGE`).
- 등급 단어(큰 성공, 간신히 성공, 아깝게 실패, 큰 실패)도 임시다. 치명타·절대성공 규칙(#321, #322)을 정할 때 어휘가 겹치면 기획자 확인이 필요하다.

### 명중

공격 모션 → 주사위 굴림(굴림음) → 결과 확정(결과음) → 명중이면 피해와 타격음(`hit.ogg`) 순서다. 명중 성공 시 결과음과 타격음이 연달아 난다. 빗나가면 실패 결과음만 난다. 명중굴림은 연출이 끝난 뒤 피해를 내므로, 절대면이 나오면 결과를 더 오래 보인 만큼(약 0.4초) 뒤따르는 처리가 늦는다. 절대성공은 피해와 타격음이, 절대실패는 빗나감 표시와 반격이 늦다.

### 절대면 연출

[#488](https://github.com/minjunkim-dev/BGLike/issues/488)에서 정했다([결정 기록](https://github.com/minjunkim-dev/BGLike/issues/488#issuecomment-6738857891)).

- 카메라는 움직이지 않는다. 정수 배율([ADR 0002](adr/0002-resolution.md))과 플레이어가 옮겨 둔 화면을 지킨다.
- 슬로모션은 넣지 않는다. 적 턴 4배속이 `Engine.time_scale`을 쓰므로 전역 시간을 바꾸지 않는다.
- 아군의 명중굴림에서 절대면이 나오면 결과 표시 시간만 일반 0.5초에서 약 0.9초로 늘린다. 기본값(`개발 결정`, 아래 [속도](#속도))이며 플레이 피드백으로 조정한다. 구현은 [#491](https://github.com/minjunkim-dev/BGLike/issues/491)이다.
- 독 제거·회전회오리·만능팔 내성은 지금의 강조(큰 주사위, 노란 외곽선)만 둔다.
- 지금 절대성공에 붙는 공통 추가 이점은 없다([#322](https://github.com/minjunkim-dev/BGLike/issues/322)에서 치명타 전역 규칙을 만들지 않기로 함). 그래서 위 강도를 전역으로 다시 보지 않는다. 어떤 스킬이 절대성공 추가 효과를 가지면 그 스킬 기획에서 연출을 함께 정한다([질문 4 정리](https://github.com/minjunkim-dev/BGLike/issues/488#issuecomment-6765872690)).

### 유리·불리

- 주사위 2개를 **동시에** 굴린다.
- 적용되는 쪽을 강조하고 버려지는 쪽은 흐리게 한다.
- 굴림음은 주사위가 2개여도 한 번만 낸다. (임시 결정, 플레이 확인 뒤 조정한다.)

### 내성

- 내성굴림은 아군이 굴릴 때만 연출한다.
- 독 제거는 턴 시작에 자동으로 굴린다. 아군에 독이 겹쳐 걸렸을 때 턴 시작 연출이 길어질 수 있어 플레이 확인 항목으로 둔다.

### 빠르게 보기·건너뛰기

- 빠르게 보기(적 턴 `Space` 4배속, [#221](https://github.com/minjunkim-dev/BGLike/issues/221))는 `Engine.time_scale`을 쓴다. 주사위 애니메이션도 같은 방식으로 빨라지게 만든다.
- 건너뛰기를 쓰면 굴림 애니메이션과 굴림음은 생략한다. 결과 숫자·색상·결과음은 짧게 남긴다.
- 건너뛰기 기능은 아직 없다. 주사위 연출을 위해 먼저 만들지 않고, 그 기능을 개발할 때 함께 만든다.

### 속도

굴림 UX는 매우 빠르게 끝나야 한다. `개발 결정`(2026-11-15, [#565](https://github.com/minjunkim-dev/BGLike/pull/565)): 지금 값(굴림 0.45초 + 결과 0.5초, 절대면 명중 결과 약 0.9초, 페이드 0.3초)을 기본값으로 정한다. 근거는 한 굴림이 1초 안팎에 끝나는 턴제 택티컬의 관행과 #491·#514의 플레이 피드백이다. 대안은 굴림을 0.3초로 더 줄이는 것이다. 플레이 피드백이 오면 바꾼다.

## 구현 길잡이

- 굴림 결과는 `CombatChecks`가 즉시 확정한다. 연출은 확정된 `RollResult`를 보여 주기만 한다. 규칙과 연출을 섞지 않는다.
- `attack_animation`처럼 `await` 훅을 두어 연출이 끝난 뒤 다음 단계로 넘어가게 한다. 훅이 없으면 즉시 넘어가므로 테스트는 연출 없이 돌린다.
- 카테고리를 호출 지점에 코드로 박지 않고 한 곳에서 카테고리별 연출을 정한다. 대결이 확정될 때 한 곳만 고치면 된다.

## 구현 상태

| 항목 | 상태 |
|---|---|
| 명중·내성굴림(독 제거·회전회오리·만능팔·기름 미끌거림·독안개) 연출 | 구현. 아군이 굴릴 때만 보인다. |
| 연출 지점 | `CombatActions.roll_animation` 훅. 명중·회전회오리는 연출이 끝나길 기다린 뒤 로그와 피해를 낸다. 기다리는 동안 전투가 끝나면(전투 포기 등) 결과를 적용하지 않는다. 독 제거와 만능팔은 처리를 멈추지 않는다. |
| 이어지는 굴림 | 먼저 온 굴림부터 결과가 닫힐 때까지 하나씩 보인다. 기다리지 않는 굴림이 짧은 간격으로 이어져도 앞 결과의 숫자·색·결과음이 모두 나온다. 기다리는 굴림(명중·회전회오리)이 보이던 굴림 뒤에 오면 그 결과가 닫힌 뒤 굴리고, 자기 연출을 마친 뒤 돌아온다([#420](https://github.com/minjunkim-dev/BGLike/issues/420)). |
| 화면 | 턴 순서 막대 아래 가운데, `CombatDiceRollView`. 주사위, 합계 게이지, 기준값, 판정 단어 순으로 세로로 쌓는다. HUD 위에 그리며 입력을 막지 않는다. |
| 시간 | 굴림 0.45초 + 결과 0.5초(`TUMBLE_TIME`, `HOLD_TIME`). 명중굴림의 절대성공·절대실패면은 결과를 약 0.9초 보인다(`ABSOLUTE_HIT_HOLD_TIME`, [#488](https://github.com/minjunkim-dev/BGLike/issues/488) 결정, [#491](https://github.com/minjunkim-dev/BGLike/issues/491)). 내성굴림의 절대면은 강조만 두고 시간은 그대로다. 결과 표시가 끝나면 0.3초 동안 페이드아웃하고 숨는다(`FADE_TIME`, [#514](https://github.com/minjunkim-dev/BGLike/issues/514), 2026-11-11 플레이 피드백). 차례는 페이드를 기다리지 않고 넘겨, 다음 굴림과 피해 표시가 늦어지지 않는다. 페이드 중에 다음 굴림이 오면 페이드를 끊고 새 굴림을 보인다. 기본값(2026-11-15 `개발 결정`, 위 [속도](#속도))이며 플레이 피드백으로 조정한다. |
| 소리 | 자체 합성 임시음 3개(`dice_roll`, `roll_success`, `roll_fail`). 자산 선정은 개발자가 한다. 같은 소리가 앞 소리가 끝나기 전에 다시 나도(4배속 등) 끊지 않고 겹쳐 재생한다. |
| 이어하기 재실행 | 연출하지 않는다. |
| 건너뛰기 | 건너뛰기 기능이 없어 아직 연결하지 않았다. |

독 제거를 기다리지 않는 이유: 턴 시작 처리는 저장과 턴 전환 사이에서 한 번에 끝나야 한다. 굴림은 이미 확정돼 있어 연출만 늦게 보여도 규칙은 달라지지 않는다.
